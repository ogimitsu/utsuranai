（下の文は全体で 473 字）

このプロジェクトは、校内ICT担当の「教室の機器トラブルの知識が記録されず、異動と同時に学校から消える」課題を、先生の1タップで記録が溜まり、年度末に次の担当への引継ぎ文書になる仕組みに変えるWebアプリです。
授業開始直後、電気科2年でプロジェクターが映らない。先生は教卓のQRを読み、「映らない」を押す。その教室の機器・ケーブルやリモコンの場所・過去の記録を知ったエージェントが、はい／いいえの質問を最大2つして、手順を3行で返す（1〜2秒）。直ったら原因を1タップ。文章は書かない。直らなければ予備機の場所を案内し、写真1枚の所見つきでICT担当に知らせる。ICT担当には未対応チケット・原因の内訳・繰り返す教室が見え、履歴からの「確認ポイント」の提案を承認すると、先生の画面に1行だけ載る。年度末に「引継ぎ」を押すと、1年分の記録・業者・予備機・行事が次の担当向けの文書になる。件数や寿命の数字はコードが集計し、AIは言葉にするだけ。AIが止まっても手順集で動き、生徒の個人情報は持たない。作っているのは、県立工業高校のICT担当本人です。

## 開発中に一番詰まった場面を1つ *

①何を作ろうとしていましたか
先生のスマホで動く一次対応エージェント。症状を押すと、はい／いいえで答えられる質問を最大2つして、手順を3行で返す。Claude Haiku 5.5 に返答用のツール呼び出しを強制して、「質問」「手順」「引き継ぎ」の3種に構造化していました。

②Claude にどのように指示しましたか
システムプロンプトに教室の事実（機器、ケーブルやリモコンの場所、手順集、最近の記録）を載せ、「質問は最大2つ」「会話にすでにある質問は二度と聞かない。答えが『いいえ』『わからない』でも次は手順を示す」と書き、2回目以降の呼び出しには先生の答えを含む会話履歴を渡しました。

③何が起きましたか
「いいえ」と答えたあと、直前と同じ質問がそのまま返ってきました。3回試して3回とも同じで、プロンプトの規則を強めても変わりませんでした。

④期待していた結果と何が違いましたか
期待は「いいえ」の次に手順3行が出ること。原因はプロンプトではなく、こちらが渡していた会話にありました。最初の呼び出しだけ「症状：映らない」を伝え、2回目以降は履歴だけを渡していたので、会話が assistant の質問から始まり、モデルは症状を知らないまま履歴を見ていました。

④どのように対処しましたか
会話を必ず「症状：映らない。どうすればいいですか」という先生の一言から始めるように直したところ、3回中3回、場所つきの手順3行が返るようになりました。教訓は「モデルの出力がおかしいとき、まず自分が渡した入力を丸ごと読む」。Claude Code にブラウザを操作させてデモ台本どおりに通し操作したことで見つかった不具合で、API を叩くだけのテストでは出ませんでした。

## 開発に必要な公式の情報が十分見つけられましたか？ *

おおむね見つかりました。モデル名や現行の API の形は Claude Code 内の claude-api スキルで確認でき、ここで「Sonnet 5.5 はツール呼び出しの強制（tool_choice）を 400 で拒否する。Haiku 5.5 は受け付ける」と事前に分かったので、Sonnet 側は構造化出力（zod スキーマ）に切り替えて実装しました。足りなかったのは、こうした「モデルごとに使える機能の違い」を一覧で見られる場所と、日本語での実例です。

## Claude を使った感想と改善してほしい点 *

①日本語や日本の業務で使う立場から気づいた欠点と利点（具体例）
利点：先生向けの短い日本語（「リモコンは教卓右の引き出し」「主電源は教卓裏の電源タップ」）を、渡した事実のとおりに自然に書きます。引継ぎ文書のような学校の書類の文体（題・作成日・箇条書き）もほぼ指示どおりに出ます。
欠点：「年度」を渡さないと4月始まりで数えないので、年度と件数の集計はすべてコード側で行い、AIには結果だけ渡しました。また、質問を「AですかBですか」の二択で書きたがり、はい／いいえのボタンと合わなくなることがあり、規則として書く必要がありました。渡していない事実（電源の場所など）を聞かれると、それらしい場所を作ってしまうことがあり、事実を必ず渡す設計にしました。

②他の AI ツールと比べて劣る点と優れる点
比較なし

③一つだけ直せるとしたら何か、その改善で何が作れるようになるか
Sonnet 5.5 でもツール呼び出しの強制を使えるようにしてほしい。一次対応（Haiku）と提案・文書（Sonnet）で「構造化して返す」手段が違うため、二通りの実装を持っています。同じ手段で書ければ、モデルの差し替えだけで「急ぐ場面は速いモデル、夜間の分析は深いモデル」を切り替えられ、学校ごとの規模に合わせた運用が1つのコードで作れます。
