## プロジェクト概要（短い版・約200字）

教室で「プロジェクターが映らない」と呼ばれる校内ICT担当のための道具です。教卓のQRから開くページが、その教室の機器を知った上で手順を3行で返し、直ったら先生は原因を1タップするだけ。文章は書きません。その1タップが溜まり、年度末に日付を進めて押すと、1年分の記録・確認ポイント・業者・予備機が次の担当向けの引継ぎ文書になります。引継ぎファイルは、もう書きません。

## プロジェクト概要（長い版・約600字）

県立高校で情報系の学科を教えながら、校内ICT担当として教室の機器トラブルの一次対応を引き受けています。「映らない」で呼ばれるのは月に3回ほど。直すのは2分。中身は入力切替の番号違い、ケーブルのコネクタの傷み、電子黒板の無線切れの繰り返しです。問題はその2分がどこにも残らないこと。知識は担当者の頭にだけ溜まり、異動と同時に学校から消えて、次の担当が同じ1年をやり直します。日本の公立学校では毎年4月にこれが全国で起きています。

「映らないノート」は、この一次対応を先生のスマホで完結させ、記録を運用の副産物として溜める仕組みです。教卓のQRを読むと教室ページが開き、症状を1つ押すと、その教室の機器・ケーブルやリモコンの場所・過去の記録を知ったエージェントが、はい／いいえで答えられる質問を最大2つして、手順を3行以内で返します。直ったら原因を1タップ。直らなければ予備機の場所を案内し、写真1枚の所見つきでICT担当に知らせます。ICT担当側では未対応チケット、原因の内訳、繰り返す教室、ランプ寿命が見え、履歴から「この教室で毎回確認すること」の提案が届きます。人が承認した1行だけが先生の画面に載ります。年度末に「引継ぎ」を押すと、1年分の事実が次の担当向けの文書になります。

設計で守ったこと：AIが止まっても手順集で動く／生徒の個人情報を持たない／台帳・手順・履歴は人が読めるJSON／件数や寿命の数字はコードが集計し、AIは言葉にするだけ。だから4月から本物の学校で使えます。

## Claude利用に関する質問（想定問答）

### どのように Claude を使いましたか

実行時は用途でモデルを分けています。

- 一次対応（先生は30秒しか待てない）：Claude Haiku 5.5。ツール呼び出しを強制して返答を「質問／手順／引き継ぎ」の3種に構造化し、画面はボタンだけで進みます。教室の事実（機器・場所・手順集・最近の記録）をプロンプトキャッシュに載せて 1〜2 秒で返します。
- 確認ポイントの提案：Claude Sonnet 5.5 ＋ 構造化出力（zod）。履歴から「教室のメモに載せる1行」と根拠の件数を提案し、承認・却下は人が行います。却下は記憶され再提案されません。
- 文書生成（引継ぎ・購入計画・修理依頼）：Claude Sonnet 5.5 のストリーミング。件数・時間帯・ランプ寿命はコードで集計した「事実パック」として渡し、AIは数字を作らず言葉にするだけにしました。
- 写真の補助判定：Claude Sonnet 5.5 の画像入力＋構造化出力。写真は保存せず、所見の文章だけが残ります。
- APIキーが無い環境でも、同じ事実パックから手順と雛形を組み立てて動きます。

### Claude Code をどう使いましたか

- 11/2〜3 に Claude Code と壁打ちして課題を言語化し、`docs/SPEC.md`（仕様）と `docs/DECISIONS.md`（判断の理由）を先に固めてから実装に入りました。日ごとの経緯は `docs/BUILD_LOG.md` にあります。
- `CLAUDE.md` に用語（「視聴覚」を使わない、「確認ポイント」など）、データの約束、返答方針を固定。
- サブエージェント：`data-author`（架空校の台帳・履歴の生成）、`hurry-reviewer`（急いでいる先生の目でUIを点検。ここから「主電源の場所を言い切る」「質問は はい／いいえ で」などの修正が出ました）。
- フック：`data/*.json` を書いた直後にスキーマ検証、pre-commit で連絡先・APIキー・禁止語を検出。
- デモ台本どおりの通し操作を Claude Code のブラウザ操作で行い、同じ質問を繰り返す不具合（会話が症状の一文から始まっていなかった）を見つけて直しました。

### 工夫した点・苦労した点

- 「数字はコードが出す」。最初はAIに履歴を渡して文書を書かせましたが、件数や日付が記録と食い違うことがありました。集計をコードに移し、AIには結果だけを渡す形にしてからは、文書の数字が記録と一致します。
- 先生が答えられる形に質問を揃える。「AですかBですか」の質問に「はい／いいえ」のボタンでは答えられない。手順集の質問とプロンプトの規則を はい／いいえ 形に統一しました。
- 現場の事実に合わせる。当初は機器の「癖」を抽出する設計でしたが、実際の現場に癖と呼べるものは無く、実例は無線切れ・コネクタ破損・HDMI端子の番号違いでした。データと言葉（「確認ポイント」）を実例に寄せ直しました。

### ハッカソン後にどうしますか

実際の学校で4月から使います（台帳は手元の Excel から取り込む）。夜間に確認ポイントの提案と週報を作る常駐エージェント（Managed Agents）、一次対応と文書生成のローカルLLM差し替え（口は `src/lib/llm/` に閉じてあります）が次です。
