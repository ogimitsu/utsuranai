# 3分デモ 台本（v0.2、11/6）

**11/6 決定：実機の画面録画はしない。** アプリの画面キャプチャをスライドに貼り、合成音声でナレーションを付けた動画を `video/` で生成する（作り方は `video/README.md`、文面は `video/script.json`）。生成物は `video/out/utsuranai-demo.mp4`（2分47秒）と字幕 `.srt`。下の表は構成の元になった台本。

審査の見どころ：**前提知識がない人が理解できるか／最後まで見たくなるか**。
原則：最初の15秒で「誰の、何の痛みか」を言う。画面は常に動いている。数字は1つだけ繰り返す（月3回）。専門語を出さない。
**一番の見どころは1つ**（11/5 大谷セッションより）：**電気科2年で先生が原因を1タップした記録が、年度末の引継ぎ文書に同じ言葉「ケーブル・アダプタ」で出てくる**瞬間。0:35 のタップと 2:05 の文書を同じ教室・同じ原因でつなぎ、2:05 では文書の該当行を指で指す。残りは全部この1点のための前振り。
冒頭案（任意）：0:00 の最初の2秒に、流れ終わった引継ぎ文書の全体を一瞬見せてから教卓に戻る（「ほら、できる」を先に出す）。

撮影：スマホ画面（教室ページ）はブラウザのモバイル表示を画面録画。ダッシュボードはPC画面。ナレーションは後録りでよい。日付シミュレーターはPC側だけで使う。

### 撮影の決まり（運営ガイド「デモ動画の撮影と提出」11/6 より）

- ゴールは審査員に「もっと見たい」と思わせること。課題・解決の仕組み・実際に動いている実装の3つを明確に。コードで終始しない。審査基準（インパクト／デモ／Claude活用／深さ）を意識する
- **3分を超えた部分は見てもらえない**（提出は受け付けられるが審査員は3分で止める）。一番大事なことは冒頭に
- 画面録画ツール：Windows なら OBS Studio（無料、全画面・複数ソース）か Loom（クラウド、ウェブカメラ重ね）。手早く済ませるなら Windows 標準の Snipping Tool の画面録画でもよい
- **外付けマイクかヘッドセット**で、静かな部屋で録る。解像度は**1080p以上**。ブラウザは全画面（F11）、タスクバーは非表示、通知は Windows の「応答不可（集中モード）」をオンにしてから録る
- 書き出した動画は**最初から最後まで再生**して、音声と映像のずれがないか確認する
- 公開先は YouTube（**限定公開でよい**。「非公開」は不可）・Loom・Google Drive のどれでも。「リンクを知っている全員」に設定し、**別アカウントかシークレットウィンドウで再生できることを確認**してから貼る（運営側では検知できない）
- アップロード上限に当たったら HandBrake で圧縮
- 締切（11/8 20:00）の直前は混む。余裕を持って提出

## 撮る前に揃えるもの

- 電気科2年（`/room/r-e2`）：履歴が8件ある状態。確認ポイント承認済み
- CAD室（`/room/r-cad`）：HDMI端子3つの確認ポイント。予備に
- ダッシュボードの「確認ポイントの提案」に、承認前の提案が1つ以上残っていること（承認の瞬間を撮る）。11/5 時点で4件：機械科3年（承認に使う）、建築科2年「要確認」（却下に使う。根拠が弱い提案を人が止める場面）、電気実習室、電子情報実習室
- 承認・却下もブラウザから `data/devices.json` に書き込まれる。撮影後は `git status` を見て `git show HEAD:data/devices.json > data/devices.json` で戻す（incidents.json も同様）
- 未対応チケットが2〜3件あること（11/5 時点で3件：進路指導室・建築製図室・電子情報科3年）
- APIモードで撮る（手順集モードでは「AI」バッジが「手順集」になる）。撮影前に `.env.local` のキーと残高を確認
- 日付シミュレーターを 2027-03-31 にしたときの引継ぎ文書が、表崩れなく出ること（11/4 にテンプレート／AI の両方で確認済み。AI版は見出し8節・表3つ、購入計画は題と作成日つき）
- ブラウザのズームは 125%、モバイル表示は 390×844
- 教卓QRカードの実物を1枚印刷しておく（`/admin/qr` → 印刷。A4に6枚。0:15 と 2:40 の静止画に使う）
- 録画はローカル（`npm run dev`）で。公開URLは記録が残らないため（`docs/DEPLOY.md`）
